## Правила для ИИ-контрибуций

Мы принимаем контрибуции, созданные с использованием ИИ, но они должны соответствовать требованиям проекта. ИИ — это инструмент, а не замена инженерной ответственности: код, сгенерированный бездумно или без последующей проверки, будет отклонён так же, как и любой другой низкокачественный PR.

Обязательные требования к любым ИИ-сгенерированным изменениям:

- **Соответствие канону проекта.** Источник правды — `.agents/rules/` и `.agents/skills/`. Ознакомьтесь с ними перед отправкой PR.
- **Соблюдение правил Arcane, а не апстрима.** Код должен следовать паттернам Arcane, а не тащить легаси, кривой prediction и случайные апстрим-диффы.
- **Обязательная поддержка prediction.** Геймплейные изменения должны корректно работать в предсказании.
- **Обязательная локализация.** Все пользовательские строки должны быть локализованы согласно правилам Arcane.
- **Правильное размещение кода.** Shared / Server / Client — строго по назначению логики.
- **Корректный networking.** `NetEntity`, `Dirty`, networked-компоненты — по канону Arcane.
- **Narrow diff.** Никаких массовых правок апстримных файлов и fork-only логики внутри них.
- **Соблюдение кодстайла.** Нейминг методов подписки и зависимостей, нейминг локализации, использование `Entity<T>`, схемы `On -> Try -> Can -> Do`, `[DataField]` и `ProtoId<T>` / `[Prototype]` без легаси-стиля.
- **Отсутствие шума на ревью.** Изменения не должны порождать тупые замечания и требовать многократных доработок.
- **Отсутствие wholesale-генерации.** Полностью сгенерированные файлы, autogenerated-документация, сгенерированные описания issue/PR без редактирования — не принимаются.

При продвинутом использовании учитывайте, что мы используем Trauma engine и [QuietToolbox](https://github.com/Trauma-Station/QuietToolbox).

## Сборка

</div>

</div>

### Windows

> 1. Клонируйте данный репозиторий.
```shell
git clone https://github.com/ArcaneSS14/arcane-station.git
```

1. Откройте коммандную строку в папке репозитория и введите команду для того, чтобы скачать движок игры.

```shell
git submodule update --init --recursive
```

1. Следующим этапом идёт билд-билда, для этого нужно ввести команду с указанием того, для чего вы билдите, для этого нужно написать Release, Tools или Debug.

```shell
dotnet build --configuration Release/Tools/Debug
```

[!TIP]
К примеру Release - полная версия, Tools - урезаная версия, Debug - урезаная версия, но которая будет вылетать при любой ошибке. В большинстве случаев вам хватит Tools, что-бы не перенапрягать машину.

1. Далее вам требуется запустить сервер с клиентом, для этого есть несколько способов.

· 4.1. Командами, в конце так же можно указать вместо Tools любой интересующий вас тип.

```shell
dotnet run --project Content.Server --configuration Tools
```

```shell
dotnet run --project Content.Client --configuration Tools
```

· 4.2. Запуск .bat файла, который автоматически выполнит те же команды.

```shell
Scripts/bat/runQuickAll.bat
```

1. Подключитесь к localhost в появившемся окне и играйте!
